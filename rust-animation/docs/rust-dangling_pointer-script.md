## 镜头 1：引用的作用域

**时间：0—16 秒**

### 旁白

> 我们在 `get_msg` 中创建了一个 `String`。
>  但 `msg` 只属于这个函数，一旦函数执行结束，它的数据就会被释放。
>
> 如果这时把 `&msg` 返回出去，调用方拿到的引用就会指向已经失效的数据，这就是悬垂引用。
>
> 好在 Rust 会在编译阶段直接阻止这种情况。
>  因为引用不能比它指向的数据活得更久。

### 代码

```rust
fn main() {
   let msg = get_msg();
    println!("{}", msg);
}

fn get_msg() -> &String {
    let msg = String::from("hello");
    &msg
}
```

### 画面

- 标题：“悬垂引用”

- `get_msg` 函数中的 `msg` 变量在函数中自由的游动（就像小鱼一样），一旦游出函数范围`msg` 则变为👻（幽灵），表示已被释放

- 随后穿着保安制服的 Ferris 出现，接着函数返回值处（`&String`）底部出现红色波浪线，表示出现编译失败

- 下半部分的Box显示：”引用不能比它指向的数据活得更久“

## 镜头 2：如何正确返回函数中的数据？

**时间：16—34 秒**

### 旁白

> 那该怎么把这个字符串返回出去呢？
>  很简单，不要返回引用，而是直接把 `String` 的所有权转移给调用方。
>
> 这样函数结束以后，数据不会被释放，而是由新的所有者继续管理。

### 画面

- 复用“镜头一”的画面，将错误信息删除

- 虚线箭头指向函数中 & 的符号，下半部分的Box显示：”将引用改为所有权转移“

- 代码更新：

  ```rust
  fn main() {
      let msg = get_msg();
      // 以上代码等价于：let msg =  String::from("hello");
      println!("{}", msg);
  }
  
  fn get_msg() -> String {
      let msg = String::from("hello");
      msg
  }
  ```

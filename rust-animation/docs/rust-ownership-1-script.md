### 镜头6：使用引用进行借用

**时间：43—55 秒**

**旁白：**

> 这时就可以使用引用，也就是借用，只需要在 `xiaoming_key` 前面加上一个 `&`。
>
> ```rust
> let xiaoming_key = String::from("电动车钥匙");
> let zhangsan_key = &xiaoming_key;
> 
> println!("张三临时使用：{}", zhangsan_key);

>

   ```rust
   let xiaoming_key = String::from("电动车钥匙");
   let zhangsan_key = xiaoming_key;
   
   println!("张三临时使用：{}", zhangsan_key);
   println!("小明仍然拥有：{}", xiaoming_key);
   ```

4. 在中间层上方显示一个 “&”符号，然后虚线指向 xiaoming_key 的前面

### 镜头9：Rust 为什么要这样设计？

**时间：约 20 秒**

**旁白：**

> 因为像 `String` 这样的数据，最终必须有人负责释放它占用的内存。
>
> 如果小明和张三都认为自己拥有同一份数据，那么当他们离开作用域时，就可能同时尝试释放同一份资源。
>
> 这可能导致 **Double Free（重复释放）**。
>
> Rust 的解决办法很直接：
>
> 一份资源，只能有一个明确的所有者。
>
> 当所有权发生 Move 后，释放资源的责任会转移给新的变量，原来的变量立即失效。
>
> 而 Borrow（借用）只提供临时访问权，并不会获得释放资源的责任。
>
> 这样，Rust 就能在没有垃圾回收器的情况下，把很多内存问题提前阻止在编译阶段。
>

**画面：**


### 镜头 10：Copy 补充与结束

**时间：61—68 秒**

**旁白：**

> 补充一点：不是所有赋值都会发生 Move。像 `i32` 这类实现了 `Copy` 的类型，会直接复制；而 `String` 默认会转移所有权。

**画面：**


标签：

```text
Copy
```

```rust
let s2 = s1;

println!("{s1}"); // Error
```

标签：

```text
Move
```

```text

数据到底归谁负责？
```

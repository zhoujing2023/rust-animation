## Motion Canvas 分镜表

### 镜头 1：可变和不可变

**时间：0—7 秒**

**旁白：**

> Rust 为什么允许创建多个不可变引用，却只允许一个可变引用？
>  更奇怪的是，这两种引用还不能同时存在。
>  我们先从不可变引用和可变引用的冲突开始。

**画面：**

代码编辑器卡片内容：

```rust
let mut text = String::from("hello");

let r1 = &text;
let r2 = &text;      // OK
let r3 = &mut text;  // Error

println!("{r1}, {r2}");
```

* 使用 `Code` 组件展示代码；

### 镜头 2：不可变引用与可变引用的冲突

**时间：7—22 秒**

**旁白：**

> 这里是`reader` 对 `document` 的不可变引用。
>  在 `reader` 仍然需要使用的期间，Rust 会保证它看到的数据不会被修改或替换。
>
> 所以，当我们试图把“版本 A”替换为“版本 B”时，编译器会直接阻止这次操作。
>
> 因为一旦允许修改，不可变引用所依赖的数据就发生了变化。
>
> 不过，如果所有人都只读取，而不修改数据呢？

**画面布局：**

**上半部分：**

代码编辑器卡片从下方进入：

```rust
let mut document = String::from("版本 A");
let reader = &document;
document = String::from("版本 B");
println!("{}", reader); 
```

依次高亮：

1. 创建 `document`
2. 创建`reader`
3. 更新`document`
5. 第三行出现红色波浪线，随后弹出：

```text
cannot assign to `document` because it is borrowed
```

5. 将三行标记删除线，随后消失

6. println!

**动画建议：**

* 使用 `Code` 组件展示代码；
* 高亮按行移动；
* 报错出现时让代码框轻微震动；
* 错误文字停留至少 1 秒。

**下半部分：**

三个 Box 分别表示：document，reader，版本A。

三者的关系：`document` 使用实线指向 `版本A` （表示拥有数据的所有权），`reader` 通过虚线指向 `版本A`（表示引用）。

（分配新内存）画面中出现个 `版本B` 的 Box，`document` 试图将实线从指向 `版本A` 改为指向 `版本B`，结果 Ferris 出现（Rust 的吉祥物，也就是那只螃蟹）把实线箭头给弹了回去（表示不可变借用仍然有效时，不能通过所有者修改或替换被借用的数据）

**底部：**

显示 Box ，内容为：不可变借用有效期间，数据不能被修改

### 镜头 3：共享读取

**时间：22—34 秒**

**旁白：**

> 不可变引用只能读取数据，不能修改数据。
>
> 所以无论有一个、两个，还是三个读者，数据本身都不会被其中任何一个读者改变。
>
> 多个读取者之间不会互相干扰，因此 Rust 允许多个不可变引用同时存在。
>
> 也就是说，读取可以共享。
>  但可变引用遵守的就是另一套规则。

**画面布局：**

**上半部分：**

代码编辑器卡片内容：

```rust
let doc = String::from("hello");
let reader_1 = &doc;
let reader_2 = &doc;
let reader_3 = &doc;
println!("{},{},{}", reader_1, reader_2, reader_3);
```

**动画建议：**

* 使用 `Code` 组件展示代码；

**下半部分：**

五个对象，分别是：doc（纸质文件），hello（文件内容），reader_1（阅读者），reader_2（阅读者），reader_3（阅读者）。

（之间的关系）doc 通过实线指向 hello，其它通过虚线指向 hello

### 镜头 4：独占修改

**时间：34—44 秒**

**旁白：**

> 对于同一份数据，Rust 不允许同时存在两个有效的可变引用。
>
> 第一个可变引用仍然有效时，再创建第二个可变引用，就会编译失败。
>
> 不过，这里的“同时存在”，到底是怎么判断的呢？
>  Rust 真正检查的是两个借用范围有没有发生重叠。

**画面：**

代码编辑器卡片内容：

```rust
let mut data = 42;

let w1 = &mut data;
let w2 = &mut data; // Error

println!("{w1}");
```

**动画建议：**

* 使用 `Code` 组件展示代码；

### 镜头 5：非词法生命周期

**时间：44—85 秒**

**阶段一**

**旁白：**

> 看下面这段代码。
>  它既创建了不可变引用，也创建了可变引用，那为什么可以正常编译呢？

**画面：**

标题：非词法生命周期

代码编辑器卡片内容：

```rust
let mut doc = String::from("hello");
let r1 = &doc;
println!("{}", r1);

let w1 = &mut doc;
*w1 = String::from("world");
println!("{}", w1);
```

**阶段二**

**旁白：**

> 关键就在 `r1` 的最后一次使用位置。
>
> `r1` 在第一个打印语句之后，就不会再被使用了。
>  因此，它对应的不可变借用也在这里结束。
>
> 后面创建的 `w1`，并没有和 `r1` 的借用范围发生重叠。
>  所以这段代码可以正常编译。
>
> 这种根据引用最后一次使用的位置来判断借用范围的机制，就叫非词法生命周期。

**画面**

标题：非词法生命周期

代码编辑器卡片内容：

```rust
let mut doc = String::from("hello");
let r1 = &doc;
println!("{}", r1);

let w1 = &mut doc;
*w1 = String::from("world");
println!("{}", w1);
```

通过多个矩形作为背景色拼接标记出 r1 和 w1 的借用范围（类似于在IDE中通过鼠标选中引用的创建处并拖动鼠标至引用最后一次使用处的背景色效果）

**阶段三**

**旁白：**

> 多个可变引用也是一样。
>
> `w1` 使用结束以后，它的可变借用也随之结束。
>  这时再创建 `w2`，两个可变借用的范围并不重叠，所以代码仍然合法。

**画面**

标题：非词法生命周期

代码编辑器卡片内容：

```rust
let mut text = String::from("text");

let w1: &mut String = &mut text;
*w1 = String::from("w1");

let w2: &mut String = &mut text;
*w2 = String::from("w2");

println!("text value: {}", text);
```

通过多个矩形作为背景色拼接标记出 w1 和 w2 的借用范围（类似于在IDE中通过鼠标选中引用的创建处并拖动鼠标至引用最后一次使用处的背景色效果）

**阶段四**

**旁白**

> 但只要我们在 `w2` 创建之后，再次使用 `w1`，情况就不同了。
>
> 因为 `w1` 的最后一次使用位置被推迟，它的借用范围也会随之延长。
>
> 此时，`w1` 和 `w2` 的可变借用发生了重叠，编译器就会报错。

```rust
let mut text = String::from("text");

let w1: &mut String = &mut text;
*w1 = String::from("w1");

let w2: &mut String = &mut text;
*w2 = String::from("w2");

println!("w1 value: {}", w1);
println!("text value: {}", text);
```

**画面**

标题：非词法生命周期

代码编辑器卡片内容：

通过多个矩形作为背景色拼接标记出 w1 和 w2 的借用范围，重叠处的作用域出现红色背景（类似于在IDE中通过鼠标选中引用的创建处并拖动鼠标至引用最后一次使用处的背景色效果）

**动画建议：**

* 使用 `Code` 组件展示代码；

### 镜头 6：总结

**时间：85—95 秒**

**旁白：**

> 所以，Rust 的引用规则可以总结为：
>
> 多个不可变引用可以共享读取；
> 同一份数据只能存在一个有效的可变引用；
> 而它们是否冲突，取决于借用范围有没有发生重叠。
>
> 这就是 Rust 中不可变引用、可变引用，以及非词法生命周期之间的关系。
>
> 下一期我们来讲讲：《Rust 生命周期标注 `'a` 到底在标注什么？》

**画面**

标题：总结

第二个Box的内容：同一份数据只能存在一个有效的可变引用

第三个Box的内容：借用范围发生重叠-编译失败

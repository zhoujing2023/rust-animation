### 镜头 4：映射回 Rust 代码

**时间：28—38 秒**

**旁白：**

> 代码中的情况也是一样。这一行并没有复制一份新的字符串，而是把所有权从 `xiaoming_key` 移动给了 `zhangsan_key`。

**画面布局：**

上半部分展示代码：

```rust
let xiaoming_key = String::from("电动车钥匙");

```



**旁白：**

> 这个过程叫做 Move。所以从这一刻开始，`xiaoming_key` 就失效了。

* 只让所有权连线从 `xiaoming_key` 切换到 `zhangsan_key`；

### 镜头6：使用引用进行借用

**时间：43—55 秒**

**旁白：**

但如果张三只是临时使用一下钥匙，并不打算把它拿走呢？

这时，只需要在 `xiaoming_key` 前面加上一个 `&`。

```rust
let xiaoming_key = String::from("电动车钥匙");
let zhangsan_key = &xiaoming_key;

println!("张三临时使用：{}", zhangsan_key);
println!("小明仍然拥有：{}", xiaoming_key);
```

`&` 表示创建一个引用，也就是借用。

`zhangsan_key` 可以通过引用访问这份数据，但它没有取得所有权。

正式钥匙始终留在小明手里，所以小明后面仍然可以继续使用 `xiaoming_key`。

**画面：**

1. 一级标题显示"临时使用，不拿走"

2. 二级标题显示“在变量前加一个&”

3. 中间层显示代码内容：

   ```rust
   let xiaoming_key = String::from("电动车钥匙");
   let zhangsan_key = xiaoming_key;
   
   println!("张三临时使用：{}", zhangsan_key);
   println!("小明仍然拥有：{}", xiaoming_key);
   ```

4. 在中间层上方显示一个 “&”符号，然后虚线指向 xiaoming_key 的前面

5. 在 xiaoming_key 的前方插入“&”符号

6. 选中最后两行打印内容，在右侧显示“成功标识”

### 镜头 9：讲解

**时间：40 秒**

**旁白：**

> 因为对于 `String` 这样的数据，最后必须有人负责释放它占用的内存。
>
> 如果小明和张三都认为自己拥有同一把钥匙，那么当他们离开作用域时，就可能同时尝试释放同一份资源。
>
> 这就是“双重释放”。
>
> Rust 的解决办法很直接：
>
> 一份资源只能有一个明确的所有者。
>
> 所有权发生 Move 后，原来的变量立即失效；而借用只提供临时访问权，不负责释放数据。
>
> 这样，Rust 就能在没有垃圾回收器的情况下，把很多内存问题提前挡在编译阶段。

**画面：**

标题：一份资源只能有一个明确的所有者

第一阶段：假设有多个所有者

let xiaoming_key ，let zhangshan_key 两个变量使用实线同时连接着 String::from("钥匙")，画面是一个三角形的关系，String 在上方，xiaoming_key 在左下，zhangshan_key 在右下，表示着两者都是 String 的所有者。

第二阶段：双重释放

此时 xiaoming_key 旁边弹出“离开作用域”的tag，连接的实线断开，String 变成半透明状态（表示 xiaoming_key 已离开作用域，对 String 进行了释放操作）。接着 zhangshan_key 进行同样的操作，结果在断开实线时弹出的错误标识（表示 String 已经被释放了，不可再次释放）。

第三阶段：解决办法

依旧是三角形的关系，zhangsan_key 处于半透明状态，这次只有 xiaoming_key 和 String 有着实线关联并处于高亮状态（表示只有 xiaoming_key 拥有所有权），接着 xiaoming_key 用红色的箭头指向了 zhangsan_key （表示 xiaoming_key 被赋值给了 zhangsan_key），xiaoming_key 和 String 的实线消失并处于半透明状态，取而代之的是 zhangsan_key 的高亮状态和 String 的实线连接（表示所有权转移），最后 xiaoming_key 通过虚线和 zhangsan_key 进行关联（表示借用）

### 镜头 10：Copy 补充与结束

**时间：61—68 秒**

**旁白：**

> 补充一点：不是所有赋值都会发生 Move。像 `i32` 这类实现了 `Copy` 的类型，会直接复制；而 `String` 默认会转移所有权。

**画面：**

左侧：

```rust
let a = 10;
let b = a;

println!("{a}"); // OK
```

标签：

```text
Copy
```

右侧：

```rust
let s1 = String::from("hello");
let s2 = s1;

println!("{s1}"); // Error
```

标签：

```text
Move
```

结尾文字：

```text
Rust 所有权：
数据到底归谁负责？
```

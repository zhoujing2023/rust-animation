## Motion Canvas 分镜表

### 镜头 1：编译错误钩子

**时间：0—6 秒**

**旁白：**

> 为什么下面这段代码，只是赋值了一次，Rust 就不让我继续使用原变量了？

**画面：**

代码编辑器卡片从下方进入：

```rust
let xiaoming_key = String::from("电动车钥匙");
let zhangsan_key = xiaoming_key;

println!("{}", xiaoming_key);
```

依次高亮：

1. 创建 `xiaoming_key`
2. 赋值给 `zhangsan_key`
3. 使用 `xiaoming_key`

第三行出现红色波浪线，随后弹出：

```text
borrow of moved value: `xiaoming_key`
```

**动画建议：**

* 使用 `Code` 组件展示代码；
* 高亮按行移动；
* 报错出现时让代码框轻微震动；
* 错误文字停留至少 1 秒。

### 镜头 2：建立钥匙隐喻

**时间：6—15 秒**

**旁白：**

> 因为在 Rust 中，每一份数据都有一个所有者。这就像小明手里只有一把电动车钥匙。谁拿着钥匙，谁就能使用这辆车。

**画面：**

* 左侧：蓝色小明 Pictogram；
* 中间：黄色钥匙；
* 右侧：电动车图标；
* 小明和钥匙之间有高亮连接；
* 上方显示：

```text
Owner
```

* 下方显示：

```text
一份数据，一个所有者
```

**视觉关系：**

```text
小明 ——持有——▶ 钥匙 ——控制——▶ 电动车
```

**动画建议：**

小明、电动车分别从左右进入，钥匙由缩小状态弹出。

### 镜头 3：Move 所有权转移

**时间：15—28 秒**

**旁白：**

> 当小明把钥匙直接交给张三以后，张三就成为了新的持有者。小明手里已经没有钥匙，自然不能继续骑车。

**画面：**

* 红色张三从右侧进入；
* 钥匙从小明手中飞到张三手中；
* 小明与钥匙之间的连接断开；
* 张三与钥匙建立新连接；
* 小明逐渐变灰；
* 小明尝试走向电动车，出现红色禁止图标。

画面中央显示：

```text
Move
所有权转移
```

**关键原则：**

画面中始终只有**一把钥匙**。

不要复制出第二把钥匙，否则会破坏所有权隐喻。

### 镜头 4：映射回 Rust 代码

**时间：28—38 秒**

**旁白：**

> 代码中的情况也是一样。这一行并没有复制一份新的字符串，而是把所有权从 `xiaoming_key` 移动给了 `zhangsan_key`。

**画面布局：**

上半部分展示代码：

```rust
let xiaoming_key = String::from("电动车钥匙");
let zhangsan_key = xiaoming_key;
```

下半部分展示内存关系：

初始：

```text
xiaoming_key ─────▶ "电动车钥匙"
```

执行第二行以后：

```text
xiaoming_key    ×

zhangsan_key ─────▶ "电动车钥匙"
```

**旁白：**

> 这个过程叫做 Move。所以从这一刻开始，`xiaoming_key` 就失效了。

**动画建议：**

* 数据箱保持不动；
* 只让所有权连线从 `xiaoming_key` 切换到 `zhangsan_key`；
* 原变量卡片变灰并显示 `moved`。

### 镜头6：使用引用进行借用

**时间：43—55 秒**

**旁白：**

但如果张三只是临时使用一下钥匙，并不打算把它拿走呢？

这时，只需要在 `xiaoming_key` 前面加上一个 `&`。

```rust
let xiaoming_key = String::from("电动车钥匙");
let zhangsan_key = &xiaoming_key;

println!("张三临时使用：{}", zhangsan_key);
println!("小明仍然拥有：{}", xiaoming_key);
```

`&` 表示创建一个引用，也就是借用。

`zhangsan_key` 可以通过引用访问这份数据，但它没有取得所有权。

正式钥匙始终留在小明手里，所以小明后面仍然可以继续使用 `xiaoming_key`。

**画面：**

1. 保留上一镜头中的 Move 代码。
2. 时间倒退，钥匙从张三回到小明手中。
3. 第二行 `xiaoming_key` 前方出现一个高亮的 `&`。
4. 黄色正式钥匙继续留在小明手中。
5. 张三获得一张蓝色的临时访问证。
6. 小明与钥匙之间使用实线连接。
7. 张三与钥匙之间使用蓝色虚线连接。
8. 两行 `println!` 依次执行，并各自显示绿色成功标记。
9. 画面中央显示：

```text
Move：转移所有权
Borrow：临时访问
```

### 镜头 7：Move 和 Borrow 对比

**时间：54—61 秒**

**旁白：**

> 所以你可以先记住：所有权是把钥匙交给别人；借用则是暂时让别人使用。

**画面左右对比：**

左侧：

```text
Move
正式钥匙转移
原所有者失效
```

右侧：

```text
Borrow
临时访问
原所有者仍然有效
```

中间使用一条竖线分隔。

### 镜头 8：Copy 补充与结束

**时间：61—68 秒**

**旁白：**

> 补充一点：不是所有赋值都会发生 Move。像 `i32` 这类实现了 `Copy` 的类型，会直接复制；而 `String` 默认会转移所有权。

**画面：**

左侧：

```rust
let a = 10;
let b = a;

println!("{a}"); // OK
```

标签：

```text
Copy
```

右侧：

```rust
let s1 = String::from("hello");
let s2 = s1;

println!("{s1}"); // Error
```

标签：

```text
Move
```

结尾文字：

```text
Rust 所有权：
数据到底归谁负责？
```
